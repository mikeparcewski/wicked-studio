I'll survey the repo structure, test infrastructure, and product docs to build the test plan.## Target survey

wicked-studio is a pure HTTP/WS SPA client of wicked-crew (`/api/v1` + `/ws`), sharing only the `wicked-crew-api-types` wire contract. No server logic of its own. Test surface, as it actually exists (not just as `TEST-001-test-strategy.md` describes it — that doc is stale: it lists 3 example test files, but `tests/` actually holds **~220** vitest specs):

- **`tests/`** — 220+ Vitest specs (jsdom), covering zustand stores, API client parsing, and component behavior. Includes `tests/fixtures/fixtureBridge.ts`, a jsdom-native stand-in for the interactive-doc iframe bridge (no real iframe layout in jsdom, so rects are asserted rather than measured).
- **`testid-inventory.json`** — a committed, versioned selector contract regenerated by `scripts/generate-testid-inventory.mjs`; `tests/testidInventory.test.ts` fails CI on drift. Per its own `$doc`: the Playwright executor is **model-free** — a selector miss is a hard failure, never an agentic fallback *at execution time*.
- **`e2e/`** — ~65 Python Playwright scripts, almost all self-contained: each builds its own `dist/`, serves it from a static server on an ephemeral port, and drives a frozen-`NOW0` fixture (`uxfix_fixture.py`) — no live daemon needed. They're organized as per-slice acceptance gates tied to specific `.product/DES-*.md` docs (ux_slice*, ux2_*, uxfix_slice*, feedback_slice*, feedback2/3_slice*, vision_slice* for pixel-diff regression).
- Two **e2e scripts have a live external-service dependency**:
  - `studio_standalone_test.py` — needs a running `wicked-crew serve` daemon; proves studio builds/runs independent of crew source.
  - `interactive_wire_contract_test.py` — spawns a real `wicked-interactive` bridge from a sibling checkout; asserts studio's client only calls routes that bridge actually serves (catches invented/mock-only routes).
- Standard gates: `npm run lint`, `npm run typecheck`, `npm run build` — all deterministic, all required to merge per CI matrix.

| 9 | Selector-drift repair (existing spec fails because a testid renamed) | Live DOM, existing spec + inventory diff | **Governed agent run** — same authoring-agent path as (8), narrower scope |
| 10 | Subjective/UX judgment not reducible to a fixed assertion (e.g., "does this feel right," ambiguous DES-* interpretation) | Council review, `.product/` doc context | **Governed agent run** — routed through a council rather than a solo model, since it's a judgment call, not a pass/fail assertion |

## Key dependency chain

(1) → (2)/(3) → (4) → (5)/(6)/(7) — each layer assumes the previous is green; (6) and (7) additionally need a live daemon/bridge the deterministic executor doesn't spin up itself. (8)/(9)/(10) sit outside this chain: they're triggered by a *product* change (new DES-* slice, a rename), not by re-running the existing suite, and their output (a new/repaired spec + inventory diff) feeds back into row (4)'s deterministic set once landed.

One correctness note worth flagging separately: `TEST-001-test-strategy.md` describes a 3-file test suite and calls the Playwright layer "operator-run before every tagged release" — both are stale against the actual ~220-spec `tests/` dir and the ~65-script `e2e/` dir.
