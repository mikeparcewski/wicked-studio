## 1. Rig — a disposable, real-mode daemon in a hermetic environment (never :7701, never the operator's home)

| Concern | How the suite handles it |
|---|---|
| Daemon | Spawned per run from the installed `wicked-crew` CLI (`CREW_CLI` overrides): temp state dir, free port, **no `--stub`** — the seeds are real engine rows. Refuses :7701. Runs in **its own process group** (`start_new_session`), so every non-detached child (workers, estate-mcp) is torn down with it. |
| Environment | **Built from scratch, never inherited** (`Rig.build_env`). Pass-through: `PATH` (node, npx, git, wicked-estate and the CLI seats resolve from it), `LANG`, `USER`/`LOGNAME` (identity, not paths) — recorded as `setup.write_targets.env_passthrough`. Everything else points INTO the temp dir: a scratch `HOME`; `TMPDIR`/`TMP`/`TEMP`; `--db` → state home (crew#353's `setCrewStateHome` follows it: audit, project settings, eval history, graphs, worktrees); `WICKED_BUS_DATA_DIR` → the bus the daemon AND the bridge share (wicked-bus `paths.js`: env › `~/.something-wicked/wicked-bus`); `WICKED_HOME` → memory store; `WICKED_WORKER_HOME` → worker config home (crew#396 idiom); `WICKED_CREW_SYSTEM_SETTINGS`; `WICKED_WORKFLOWS_DIR` (else `~/.config/wicked-core/workflows`); `WICKED_STEERING_INBOX_DIR` (else `~/.wicked/steering-inbox`); `WICKED_ESTATE_EMIT_DEADLETTER` + `WICKED_APPS_EMIT_DEADLETTER` (the Rust spools that otherwise append to `~/.something-wicked/{wicked-estate,wicked-apps}` — finding 6); `WICKED_ESTATE_REPO_GRAPH_ROOT` (the engine's per-repo code graph, else `~/.wicked-estate/repo-graphs` — finding 11); `WICKED_INTERACTIVE_ROOT` → temp docs root; **`WICKED_CREW_API` → the disposable daemon's own origin** (the bridge resolves the crew daemon from it and defaults to `:7701` — crew#476); `npm_config_cache` → a scratch npm cache. Every child of the daemon inherits this env (`bridge-pool.ts defaultSpawn` passes none of its own). |
| Write-target guard | Before anything starts, every write target (the temp dir, HOME, TMPDIR, the state home, the clone, the npm cache, every path-valued `WICKED_*`) is resolved and asserted NOT to be under the operator's real home or `~/.wicked-crew` — `setup.write_targets` (a violation is a setup failure). |
| Bridge — **pinned to an exact version, resolved offline** | The pool spawns `npx --yes wicked-interactive@^0.8.1 serve --root <root>` **detached** under the scratch HOME. `Rig.pin_bridge` (a) finds the operator's already-resolved `~/.npm/_npx/<hash>` install for exactly that spec, reads the INSTALLED `wicked-interactive` version and the tarball integrity (sha512) from the cache's own lockfile, and requires version == **`BRIDGE_PINNED_VERSION` = `0.8.1`**; (b) CLONES it (APFS clonefile; read-only on the source) into the scratch npm cache under the same key and re-reads the clone's version; (c) seeds the operator's CACHED registry manifest for `wicked-interactive` (the cacache `request-cache` index entry + content blob, same layout) into the scratch cache and proves that the `^0.8.1` range resolves to the pin FROM THAT FROZEN SNAPSHOT (`caret_max`: `^0.8.1` = ≥0.8.1 <0.9.0 — the manifest cached 2026-09-09 lists 0.9.0 as `latest`, which the caret excludes); (d) the daemon's env carries **`npm_config_offline=true`**, so npx can only use the seeded manifest + the clone — a cache miss is a loud bridge-start failure, never a registry resolution (an `--offline` run WITHOUT the seeded manifest fails `ENOTCACHED`; npx resolves the range against the manifest even with a warm `_npx` install). Everything lands in `setup.bridge` = `{pinned, version, integrity, resolved, path, scratch_path, cloned_version, registry_manifest{versions, dist_tags, cached_at, resolves_to}}`. No cache, a version drift, a missing integrity, a manifest that resolves elsewhere, or a failed clone is a **setup failure** (`report.ok=false`, step `bridge_pin`). At teardown the identified bridge must have run FROM the scratch clone, the clone must still be 0.8.1, the bridge's lock must self-report 0.8.1, and the scratch cache must have gained NO content blob — otherwise `bridge_not_from_pinned_cache` fails the verdict. **Why the pin matters:** 0.8.1 has no `DELETE /api/docs/:doc`; that is exactly the studio#213 expected gap the delete rows assert (CLN-1a–d, ISO-D, ISO-DD). A different bridge would flip those rows (to xpass, or to a crew#472 leak) — the results describe THIS bridge, by bytes. |
| Agents | Interactive agent answering is **disabled** (`--no-interactive-{draft,edit,chat,demo}-events`): doc/demo creation yields a real registry row (placeholder v0), no generation run. Exactly **one** governed scenario (TST-1) runs, serialized, and its gate is **rejected**. |
| Repository | A `git clone --local` of this checkout at HEAD, inside the temp dir (this checkout is a linked worktree; a run's own `git worktree add` from inside it would write into the main checkout's `.git/worktrees`). The clone's tracked `.codegraph/estate.db` is removed first (finding 7). Registered over the API (setup, labelled); the built-in `onboarding` workflow (two **tool** phases, no agent, no council) is waited on. |
| Startup | Bounded for real: a reader thread pumps the daemon's stdout to the log and (during startup) onto a queue; the main thread waits on the queue with the remaining deadline (90 s). A silent daemon, a dead daemon (EOF) and a late daemon all end in a group stop + a setup failure carrying the log tail. |
| Build identity | **Enforced by BYTES**: the served `index.html` and every `/assets/*` it references are fetched, SHA-256'd, and each must equal the same path under THIS worktree's `dist/` build (`npm run build`; `compare_build`). A mismatch, a missing asset, or no `dist/` is a setup failure (the results would describe another revision). Both hash sets, the dist build time, the worktree HEAD and any uncommitted `src/` change land in `setup.build_identity`; the served `studioBundle` version label is recorded, not trusted. |
| Teardown — every exit path, **verdict-affecting**, **every step isolated** | The daemon and Chromium live inside ONE `try/finally`. On success, exception or interruption (SIGINT/SIGTERM): live runs on the disposable daemon are cancelled (each `POST /runs/:id/cancel` response verified, terminal state polled); the browser is closed (a close failure is recorded as `setup.browser_close_error` and is a **teardown failure**); the daemon's process group is SIGTERMed → polled (leader exit AND empty group) → SIGKILLed → polled; the detached bridge is found **by identity** — command line naming `wicked-interactive` AND our unique temp root AND a **verified** start time after our daemon — and terminated the same way. **Which pids may be signalled is decided by `plan_bridge_stop` (pure, self-tested):** only rows identified by a SUCCESSFUL `ps`; a failed `ps` signals NOTHING — not even a partially identified row — and records `bridge_enumeration_failed` (only the daemon group we spawned is stopped); a candidate with no readable start time is `bridge_identity_unverified`; `.wi-serve.json` is advisory only (symlink refused, positive-integer pid, cross-checked against the identified set) and a lock pid that is ALIVE but matches no identified process is refused AND recorded as **`bridge_unidentified_alive`** — refusing to signal it is right, calling the cleanup a success is not. `ps` runs under `LC_ALL=C` so `lstart` parses regardless of the operator's locale (an unparseable start time still yields `None` = unverified — it narrows matching, never widens it). **Every teardown step runs in its own try/except (`run_teardown_steps`)** — cancel → daemon group → log → bridge → fixture server → scratch-writes inspection → isolation scan → temp-dir removal — so a raise in one (e.g. the scratch-writes inspection) never prevents the next (the temp dir is still removed) and is recorded as `teardown_step_raised`. `teardown_failures` (pure, self-tested) turns a refused/errored cancellation, `daemon_stopped=false`, a bridge pid surviving SIGKILL, an unverified bridge identity, a failed enumeration, an unidentified live bridge, a bridge not run from the pinned clone, a browser-close error, a temp dir still present, an isolation scan that raised, any `live_scan_error`, or any step that raised into `setup.teardown.failures[]` — each lands in `findings` and **`report.ok` is false** (exit ≠ 0). The temp dir is removed (`SEED_KEEP_TMP=1` keeps it). |
| Isolation proof | Re-derived at teardown: (a) entries under the real `~/.wicked-crew` whose NAME carries this run's identifiers; (b) a **byte-scan** of every file under the operator-global wicked stores (`~/.wicked-crew`, `~/.something-wicked`, `~/.wicked`, `~/.wicked-estate`, `~/wicked-interactive`, `~/.wicked-interactive`, `~/.wicked-worker`, `~/.config/wicked-{core,crew}`) that was **modified during the run**, for this run's composite identifiers (project names, repo name, doc/demo names, rule text, import batch text, corpus scope, memory scopes/content, proposal content + ids, campaign id, feedback text, brief token, temp-dir name, project/repo/run ids — never the bare stamp, which is a substring of every same-second millisecond timestamp); (c) a read-only diff of the live `:7701` daemon's run ids before/after. Any hit is `live_touched` and **fails the process** regardless of the scenario table. **The scan fails closed at every stage**: the walk is an explicit `os.scandir` (`walk_files` — never `Path.rglob`, which swallows enumeration errors before any caller sees them), and a directory that cannot be enumerated, an entry whose type cannot be read, a file that cannot be stat'ed, or a file that cannot be opened/read is a `scan_errors` entry (path + errno + stage) → `live_scan_error` teardown failure → `report.ok=false` (an uninspected store is not a proven-clean store); every readable sibling is still scanned. What the daemon and its children wrote into the scratch HOME/TMPDIR is listed as the `HOME-WRITES` finding (finding 11). |
| Browser | Python Playwright, `chromium.launch()` headless, 1440×800, launched inside the daemon's `try/finally`. Gate toasts hidden (display-only); the gate asserted is the card **inside** the launch panel. |
| Persistence proofs | Every "survives reload" step is a real `page.goto` (full document load), never a pushState. |
| Substitutes | Steps the UI cannot perform are done over the daemon API, labelled `[SUBSTITUTE]`, then **verified through the UI**: repo registration (setup), attaching the repo to Project A (studio#207), seeding the first steering rule when the UI cannot (studio#212), archiving projects (studio#214). **Substitute producer** (memories/proposals have no UI author path — agents are the only producer): the suite runs the very `wicked-estate-mcp` binary crew spawns for `/memory*` and `/proposals*` (`core/estate-mcp-client.js`, spawn-per-call, `WICKED_MEMORY_DB` pinned) with the rig's hermetic env and the store path asserted under the temp dir — `memory.capture` (MEM-S) and `proposal.submit` (PRP-S); every management step then runs through the UI (`setup.substitute_producer` records exe, server version, calls). |
| Verdicts | `pass` / `fail` / `skip` (an ESTABLISHED environmental cause only) / `blocked` (explicit: the rig cannot make it observable within budget — reason + issue) / `xfail` (asserts the correct behaviour; the ONE assertion tied to the issue fails today) / `xpass` (a stale marker — **fails the suite**). |
| xfail hygiene | `expect_gap(cond, issue, msg)` marks the single assertion an issue excuses; every other assertion in an xfail scenario is a plain `assert` and FAILS normally. VIB-3's oracle (`disjoint_pickers_oracle`) requires both pickers non-empty and each project's own document listed before the leak can count as crew#472 — an empty-both-lists state is a FAIL. |
| Skip hygiene | **TST-1 can never skip** (`Suite.run(no_skip=True)`): a pre-gate failure is a FAIL carrying the captured cause (run status, last events, council activity, roster `signed_in` snapshot — recorded, never used as an excuse); a missing prerequisite or `SEED_GOVERNED=0` is a FAIL too. A mode surface's error is a skip only when the daemon itself answers `503 bridge_unavailable`; evals/corpus "unsupported" only when the route is 501. Everything else is a failure with the UI's text. |
| Exit code | `0` **only** when `report.ok`: no `fail`/`xpass`, `live_touched` empty, no setup failure, nothing aborted, **no teardown failure**. `--self-test` (**96 checks**) proves in-process: `report.ok=false ⇒ exit≠0`; xfail/blocked hygiene; pid identity incl. unverified start time / failed `ps`; the gate oracle incl. an execution event after the gate; a skipped/prereq-failed gate ⇒ FAIL ⇒ exit≠0; every teardown failure kind ⇒ `ok=false` (incl. `bridge_enumeration_failed`, `bridge_unidentified_alive`, `bridge_not_from_pinned_cache`, `browser_close_error`); a mocked `PermissionError` on read, on stat AND on directory enumeration ⇒ `live_scan_error` (the readable sibling still scanned; an unreadable root is an error, never clean); the campaign oracle (500 / non-list / seed unlisted / owner card missing / a foreign card on B ⇒ FAIL; B rendering the seed ⇒ the ONE expected gap; partitioned ⇒ pass); the recorder classifier (`database corrupt`, HTTP 500 + timeout, prerequisite with a 500 ack, timeout, missing ack ⇒ fail; prerequisite with a 2xx ack ⇒ blocked); bridge-stop planning (failed `ps` with a partial row ⇒ nothing signalled + failure; alive unidentified lock pid ⇒ refused + failure; dead stale lock pid ⇒ no failure; identified + matching ⇒ signalled cleanly); cleanup continuity (every step runs past a raise; the REAL `Rig.teardown` with a raising scratch-writes inspection still removes the temp dir and records the raise as a failure); the bridge pin (no cache / version drift / missing integrity ⇒ error; exact ⇒ resolves with sha512; caret resolution `^0.8.1` excludes 0.9.0; the cached manifest is copied index + blob); `ps` under `LC_ALL=C` (a non-English `lstart` ⇒ `None` = unverified); build identity by bytes; per-target cleanup rows; the persistence content oracle; the report scrub. |
